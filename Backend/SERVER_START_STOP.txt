SUPABASE SERVER: START-UP AND SHUT-DOWN
Road Quality Mapper - EE475 Team 5
==================================================================

For the Linux laptop that runs Supabase. First-time setup is in SUPABASE_SETUP.txt.

What starts by itself after a reboot:   Docker, Tailscale, Funnel, Valhalla (a Docker container),
                                        the road-matcher service (waits until Supabase is up)
What does NOT:                          Supabase (you run `supabase start`)

Road matching setup and details: ROAD_MATCHING_SETUP.txt.


------------------------------------------------------------------
START-UP (after turning the laptop on or rebooting)
------------------------------------------------------------------

1. Keep the laptop plugged in. The lid can be closed once it's running.

2. Start Supabase:

       cd ~/ee475aut26team5/Backend
       supabase start

   If it says "Cannot connect to the Docker daemon": sudo systemctl start docker

3. Check Funnel is on:

       tailscale funnel status

   It should show https://benjamin-xps139350.tailf1a20b.ts.net -> 127.0.0.1:54321.
   If it shows nothing:   sudo tailscale funnel --bg 54321

4. (Optional) Quick check that the keys are still right:

       bash checks/check_keys.sh

5. (Optional) Check road matching is up (Valhalla, matcher service, locked down):

       bash checks/check_matcher.sh

   The matcher retries every 30 s until Supabase is up, then matches any trips that ended
   while it was down. Its log:   journalctl -u road-matcher -f

   If Valhalla isn't running (docker ps doesn't list "valhalla"):
       cd ~/ee475aut26team5/Backend/valhalla && docker compose up -d
   If the matcher isn't running:   sudo systemctl start road-matcher


------------------------------------------------------------------
SHUT-DOWN
------------------------------------------------------------------

1. Stop Supabase (keeps all data):

       cd ~/ee475aut26team5/Backend
       supabase stop

   NEVER add --no-backup; that deletes the database.

2. Funnel can stay on. While Supabase is stopped, the app just gets an error and should
   retry later. To turn Funnel off completely:   sudo tailscale funnel reset
   (Then turn it back on with `sudo tailscale funnel --bg 54321` next time.)

3. Valhalla and the road matcher can stay on; they stop with the laptop and start again by
   themselves. While Supabase is stopped the matcher just retries every 30 s. To stop them
   without turning the laptop off:

       sudo systemctl stop road-matcher
       cd ~/ee475aut26team5/Backend/valhalla && docker compose stop

   (Start again: docker compose start, then sudo systemctl start road-matcher.)
   After a reboot the matcher starts again by itself, but a Valhalla you stopped this way stays
   stopped until you start it (start-up step 5). To remove both for good, see
   ROAD_MATCHING_SETUP.txt "REMOVING IT".

4. Turn off the laptop:   sudo shutdown now


------------------------------------------------------------------
AFTER PULLING NEW CODE
------------------------------------------------------------------

       cd ~/ee475aut26team5 && git pull
       cd Backend
       supabase migration up            # new migrations only, keeps data

   If config.toml changed, restart:   supabase stop && supabase start
   If the access rules changed:       bash checks/check_access.sh
   If the map functions changed:      bash checks/check_map_functions.sh
                                      bash checks/check_snapped_map.sh
   If matcher/road_matcher.py or matcher/requirements.txt changed:
                                      bash matcher/install_matcher.sh
   If valhalla/docker-compose.yml changed:
                                      cd valhalla && docker compose up -d && cd ..
   If roads/roads.lua changed:        bash roads/import_roads.sh

   Don't use `supabase db reset` once real drives are stored: it wipes everything.
